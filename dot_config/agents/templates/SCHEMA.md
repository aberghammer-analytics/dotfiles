# SCHEMA.md — Workflow Contracts (v2)

Single source of truth for layout, artifacts, and machine-readable schemas shared by
skills and the wf-* toolbelt. **Rule zero:** anything a script needs lives in
frontmatter, not prose. **Rule one:** only the toolbelt mutates machine state — skills
and workers never edit issue frontmatter, the ledger, or running-files directly.

schema_version: 2

## 1. Layout

```
repo/
├── CLAUDE.md                  # repo root; stub at riff, real at grill
├── docs/                      # human-audience prose
│   ├── VIBE.md  PRD.md  ARCHITECTURE.md  PLAN.md
│   ├── RESEARCH.md            # optional, status: living
│   ├── BACKLOG.md             # append-only findings; groomed into future slices
│   └── plans/<slice>.md       # approved slice plans (spec's gate output)
└── .claude/                   # machine state
    ├── issues/                # *.md per SCHEMA + OVERVIEW.md (generated)
    ├── ledger.jsonl           # committed — trust evidence travels with the repo
    ├── reviews/               # wf-review output — committed
    ├── logs/                  # per-attempt worker logs — gitignored
    ├── running/               # <id>.json live worker records — gitignored
    ├── review/                # lavish artifacts — gitignored
    └── run.lock               # gitignored
```

.gitignore (surgical — issues/ledger/reviews MUST travel):
`.claude/logs/  .claude/running/  .claude/review/  .claude/run.lock  .claude/*.local.*`

## 2. Stage artifacts

Doc frontmatter: `stage, status (draft|final|living), created, schema_version`.

| Doc                   | Extra required keys                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| VIBE.md               | `purpose: product\|fun\|learning`, `verdict: go\|no-go`, `est_cost_band: low\|medium\|high`        |
| PLAN.md               | `phases:` list of `{id, name, autonomy: driver\|cruise}` (defaults; binding choice at spec's gate) |
| docs/plans/<slice>.md | `slice`, `branch: slice/<name>`                                                                    |

Stage flow: vibe-check → riff (drafts) → grill (finals + scaffold + green verify;
decides, zero steps) → spec (one slice: gate → plan doc → DAG; sequences, zero
decisions) → send-it → review. Spec is the permanent re-entry point.

## 3. Issue schema

`.claude/issues/{id}-{slug}.md` — id: zero-padded 4-digit string, globally monotonic
across slices, never reused.

```yaml
---
schema_version: 2
id: "0002"
title: ...
type: task # task | checkpoint
status: ready # backlog → ready → in_progress → done | parked
phase: 1
slice: mvp
blocked_by: ["0001"]
verify: "just verify" # REQUIRED for tasks; exit 0 = pass
files:
  [src/auth/**] # expected footprint — LOAD-BEARING: wf-next excludes
  # tickets overlapping an in-flight footprint
attempts: 0 # bumped by wf-spawn only
max_attempts: 3
auto_close: false # checkpoints only
---
## Context      (self-sufficient: worker has no other memory; pointers into docs/)
## Done criteria
## Notes        (worker scratch; discovered work → docs/BACKLOG.md instead)
```

Status writers: wf-spawn (→ in_progress, attempts+1), wf-collect (→ done | ready |
parked), /review (checkpoint → done). Nobody else. Workers NEVER touch frontmatter.
parked = attempts exhausted; v1 policy: parking halts dispatch of dependents and
wakes the human.

Checkpoints: generated by spec at phase/slice boundaries; block all later work via
blocked_by; slice-end checkpoint's verify is `wf-review`. auto_close true (cruise) →
wf-collect closes on PASS; false (driver) → only /review closes.

## 4. Ledger

`.claude/ledger.jsonl`, append-only, written ONLY by wf-collect. Cost from harness
JSON output, timing from script clocks — never worker self-report.

```json
{
  "ts": "...",
  "run_id": "...",
  "issue": "0002",
  "attempt": 2,
  "result": "pass|fail|error",
  "duration_s": 341,
  "cost_usd": 1.87,
  "verify_exit": 0,
  "intervention": "retry-with-hint|"
}
```

`intervention` distinguishes coached passes from clean ones — cruise-promotion
evidence depends on it.

## 5. Git conventions

- Spec creates and checks out `slice/<name>`; the run happens there.
- Workers never commit. wf-collect commits per ticket: `wf: complete issue <id>`;
  checkpoint closure (wf-collect or /review): `wf: checkpoint <id>`.
- wf-review's default range: last `wf: checkpoint` commit → HEAD (grep that prefix).
- /review opens the PR: slice branch → main, after the human gate.

## 6. Config (env, never code)

`WF_CLAUDE_BIN` (worker harness) · `WF_CLAUDE_FLAGS` · `WF_REVIEW_BIN` (MUST be a
different vendor than the worker) · `WF_SPAWN_MODE=herdr|background` · `WF_CAP`
(default 1) · `WF_STALL_SECS` · `WF_REVIEW_MAX_DIFF_LINES`.
Template overrides: `.claude/ticket-prompt.md`, `.claude/review-prompt.md` beat the
global templates.

## 7. Versioning

Every doc and issue carries `schema_version: 2`. Every tool and skill checks it and
refuses unknown versions loudly. Migration note v1→v2: VIBE.md `effort` removed,
`purpose` added; issue `slice` added; ledger `intervention` added; layout adds
docs/plans/, .claude/{reviews,running,review}/.
